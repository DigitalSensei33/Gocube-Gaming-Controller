## BUG - Gyroscope orientation data unparseable — ASCII encoding not recognized

Description: 
Raw BLE packets for MsgOrientation were being received successfully, but 
values could not be translated into usable quaternion data. Initial 
attempts treated the payload as raw binary/numeric bytes, which produced 
garbage or unusable values.

Steps to reproduce (at the time):
1. Connect to cube, enable orientation stream
2. Parse incoming MsgOrientation packets as raw byte values
3. Attempt to derive quaternion x/y/z/w from parsed values

Expected behavior: Valid, usable quaternion values extracted from packet
Actual behavior: Values were nonsensical / unusable — data was present 
but not being interpreted correctly

### Severity: Critical (blocked all gyroscope functionality entirely)  
### Priority: High  
### Environment: Early development, pre-0.5

### **[CLOSED]**

## Root cause: 
Orientation data is transmitted as ASCII-encoded text strings 
(format: x#y#z#w), not raw binary values. Once decoded as ASCII first, 
then parsed/split on '#' delimiters, values converted correctly.

## Resolution: 
Decode payload as ASCII string before splitting/parsing, 
per official protocol format, which was later confirmed in oddpetersson's GoCube 
protocol documentation. (dev-docs/references/gocube-protocol)
